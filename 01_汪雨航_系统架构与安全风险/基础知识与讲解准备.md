# 汪雨航｜基础知识与讲解准备

## 必须讲清的因果关系

能源数字化通过测量、通信和控制提高协调能力，同时引入身份、软件与跨组织依赖。攻击面是可能接触或影响系统的入口集合；它不等于损失概率，更不等于事故后果。真正的风险需要结合有效权限、过程约束、受影响规模和恢复能力分析。[R01、R11]

IT与OT按功能区分，不按操作系统或网线颜色区分。SCADA、HMI、PLC和RTU共同构成监视与控制链，但产品可集成功能，实际系统不一定逐项独立部署。现场控制和继电保护可能不依赖同一远程通信，因此断网不必然停电。[R01]

## 可以用的教学例子

- **测量错误：**温度数据偏低可能影响判断；只有该数据被控制或人员采用、缺少交叉校验且运行状态允许影响形成，才会产生后果。此为示意，非真实事故。
- **远程维护：**VPN加密保护传输，MFA增强身份核验，最小权限约束目标与操作。三者不能相互替代。[R07、R24]
- **聚合资源：**共享平台可能让多站设备同时受到影响，但本地保护、受影响功率及电网调节能力会改变结果，不推出全国停电。[R11]
- **签名更新：**签名说明来源身份与内容未变，不证明代码无漏洞，也不证明在当前站点兼容。[R23]

## IT/OT安全比较

| 维度 | 业务IT常见关注 | 能源OT需要特别核查 |
|---|---|---|
| 后果 | 数据、服务、经营受损 | 控制状态、设备安全、供能与环境影响 |
| 时间 | 允许按业务窗口处理 | 某些闭环有严格响应时限 |
| 更新 | 常能较频繁升级 | 要评估兼容性、维护窗口、回退 |
| 扫描 | 常规主动检测较普遍 | 老旧设备可能受负载或异常报文影响 |
| 处置 | 隔离主机可能较直接 | 需先判断该主机承担的过程功能 |

这是典型差异而非绝对二分。IT同样可能安全关键，OT也有重要保密需求。[R01]

## 五问框架如何使用

先填已确认事实，再填研究判断，最后留下未知项。将“攻击者做了什么”和“运营人员做了什么”分开。结果必须有对象、范围、时间与来源；恢复分供能和可信状态两层。本框架由本组综合提出，不引用为某一标准原文。

## 最易说错的五句话

| 不应这样说 | 准确表述 |
|---|---|
| 传统电网没有网络 | 传统电网已有通信自动化，现代资源接入改变范围和依赖 |
| OT就是PLC | OT包括多种监视、控制物理过程的系统与设备 |
| 断网一定停电 | 依赖通信的功能可能受限，实际供能后果取决于本地能力和工况 |
| 有VPN就安全 | 仍需可信身份、终端、权限和会话管理 |
| 控制指令通过认证就合理 | 来源有效与业务意图合理是不同判断 |
